# 技术说明

## 技术栈

| 项 | 版本 / 说明 |
| --- | --- |
| Vue | 3（`<script setup>` 单文件组件） |
| Vue Router | 4，`createWebHashHistory`，路由懒加载改为静态导入 |
| Vite | 7，Vue 官方插件 |
| 测试 | Node 原生 `node:test` + Vitest（jsdom 环境）+ `@vue/test-utils` |
| 样式 | 原生 CSS，组件内 `<style scoped>` + 两个全局样式文件 |

运行时依赖只有 `vue` 和 `vue-router`，没有 UI 框架、没有请求库。

## 启动、测试与构建

```bash
npm install
npm run dev            # 开发服务器
npm test               # Node 测试 + Vitest
npm run build          # 生产构建到 dist/
```

`npm test` 实际执行 `node --test tests/extraction.test.mjs tests/booking-feature.test.mjs && vitest run`。
Vitest 只发现 `tests/**/*.test.js`（见 `vite.config.js` 的 `include`），避免把 Node 测试重复当成空套件。
当前状态：Node 19 个用例、Vitest 9 个文件 20 个用例全部通过；生产构建正常。

## 路由与状态

```text
/                       → 重定向到 /venues
/venues                 场馆选择
/home/:venueId          场馆首页
/reserve/:venueId       场地预约
/profile                个人中心
/my-bookings            我的预约
/my-bookings/detail     预约详情
/:pathMatch(.*)*        → 重定向到 /venues
```

- 当前场馆：`localStorage`，键 `jlu-gym-active-venue`。`getActiveVenueId()` 读取时校验 ID，
  非法值回退 `song`；`setActiveVenue()` 写入时同样做校验。首页与预约页挂载时会同步一次，
  因此从个人中心返回不会丢失最近选择的场馆。
- 演示预约：`sessionStorage`，键 `jlu-gym-mock-booking`，只保存一条记录。

## 数据模型

`src/data/venues.js`

- `venues`：以 `song`、`qianwei` 为键的场馆对象，字段包括 `id`、`name`、`address`、`phone`、
  `thumb`、`banners[]`、`description`、`sports[]`；每个 `sports` 项为 `{ name, time, image }`。
- `profile`：`{ name: '李子涵', studentId: '87240433', sex: '男' }`。
- `getVenue(venueId)`：未知 ID 回退到 `venues.song`。
- 图片通过 `new URL('../assets/original/...', import.meta.url).href` 引用，交给 Vite 处理指纹与打包。

`src/data/mockBooking.js`

- `timeSlots`：8 个固定时间段（`06:00–07:30` … `19:30–21:30`）。
- `saveMockBooking(input)`：校验场馆、项目、日期、场地号是否齐全，以及时间段是否在列表内，
  不合法时抛出 `预约信息不完整` / `预约时间段无效`；通过后把时间段拆成 `startTime` / `endTime`，
  生成 `orderNo`（`0002` + `yyyymmddhhmmss` + 10 位随机数）、`purchaseTime`、`quantity: 1`、
  `status: 'active'` 并写入 `sessionStorage`。
- `getMockBooking()`：读取并解析，内容损坏时返回 `null`。
- `cancelMockBooking()`：把状态改为 `cancelled` 后写回。
- `clearMockBooking()`：删除记录。
- 存储对象取自 `globalThis.sessionStorage`，因此测试可以注入内存实现。

## 组件

| 组件 | 职责 |
| --- | --- |
| `MobileShell` | 移动端画布容器，限制最大宽度并预留底部导航高度 |
| `BottomNav` | 固定底部导航，按 `active` 显示高亮图标，链接指向当前场馆 |
| `VenueCard` | 场馆入口卡片（圆形缩略图 + 名称 + 原站箭头图片） |
| `SportCard` | 项目卡片，展示项目名、开始营业时间并向上抛出 `reserve` 事件 |
| `BookingSetupModal` | 预约设置表单，负责校验提示与保存，成功后向父组件抛出 `saved` |
| `EntryCodeModal` | 入场码弹窗，使用固定二维码占位图与票券边框 |

## 样式约定

- 设计基准宽度 390px，桌面端画布最大 430px 居中显示（`.mobile-shell`）。
- 主色 `--brand: #7ecef4`，选中态 `--brand-deep: #69baff`，页面底色 `--page: #f6f6f6`。
- 底部导航高度 `--nav-height: 72px`，页面统一用它预留 `padding-bottom`。
- 个人中心顶部为蓝绿渐变 `linear-gradient(115deg, #83b9f6, #7be9b0)`。
- 窄屏（≤370px）下场馆卡片与项目卡片有单独的字号、间距降级规则。

## 素材与原站对照

- `src/assets/original/`：页面实际使用的本地图片（Logo、场馆照片、轮播图、项目图、导航图标、
  个人中心图标、票券边框、入场二维码占位图）。
- `reference-source/`：从原站公开前端保存的 `index.html`、`app.css` 和 11 个 Webpack 分包，
  仅用于对照与提取，运行时不加载。该目录**不纳入版本库**（已写入 `.gitignore`），
  在本地或 CI 中由提取脚本按需重建，测试不依赖它。
- `scripts/extract-original-assets.mjs` 导出 `SOURCE_FILES`、`REMOTE_ASSETS`、
  `extractDataUrlModule()`、`extractCssDataUrlRule()`，可从 DevTools 记录的 URL 重新下载全部资源，
  并把原站 CSS / JS 中的 base64 内嵌图标还原成独立文件。该脚本需要网络，日常开发与构建不需要。

## 已知限制

- 没有后端也没有持久化：预约数据只存在于 `sessionStorage`，关闭标签页就失效。
- 「在线购票」「我的邀请」「购票记录」「同行人」「选择日期区间」「场馆安排」等为纯展示控件，
  点击没有响应；这是有意保留的界面还原范围。
- 图片加载失败时没有渐变占位兜底，直接显示浏览器的破图样式。
- 预约设置弹窗的默认体育馆固定为前卫体育馆，不跟随当前选中的场馆。
